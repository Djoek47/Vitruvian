# Body Intelligence

Vitruvian turns one-time measurement into a lifelong body record. This document covers how history, change detection, fit intelligence and transformation work, and what each part can and cannot claim.

```
VR measurement ─▶ immutable snapshot ─▶ change engine ─▶ Body Evolution dashboard
                                   │                    └▶ transformation sequences / video
                                   └▶ wardrobe fit engine ─▶ "which clothes fit differently now?"
check-ins (tape, scale) ─────────────┘ (timeline only, never treated as scans)
```

## Entities (`src/intelligence/*`, store v2)

| Entity | Where | Notes |
|---|---|---|
| BodyProfile | `profileId` across passport versions | one person; created once, reused for life |
| BodySnapshot | `versions` store (encrypted) | **immutable** saved passport; a correction or new session = new snapshot |
| BodyMeasurement / AnatomicalLandmark | inside each snapshot | provenance, method, uncertainty, samples |
| BodyMesh | regenerated from the snapshot by `vitruvian-mannequin@1` | deterministic, so never stored separately and never overwritten |
| BodyChangeEvent | computed (`history.ts`) | reproducible from stored snapshots + engine version `bi-change@1` |
| Garment / GarmentMeasurement / WardrobeItem / FitFeedback | `wardrobe` collection | garment dimensions are never mixed with body dimensions |
| FitAssessment | computed (`wardrobe.ts`, `bi-fit@1`) | per area, with explanation |
| TransformationSequence | `sequences` collection | snapshot ids + view/style/duration of an export |
| ActivityRecord | `checkins`, `programs` collections | weight, tape values, workouts, readiness, programs |

The database migrates additively (v1 → v2). The passport schema goes 1.0 → 1.1 (optional fields only), and `migratePassport()` upgrades old files in memory without touching stored originals.

## Change detection: genuine change vs. noise
For each measurement in two snapshots:

* Δ, % change, Δ per week and per month.
* `u_Δ = √(u_A² + u_B² + b²)`
  * `u_A`, `u_B`: the **random** part of each measurement's uncertainty. For derived girths the shape-model error is systematic: the same model is applied to both snapshots, so it cancels in Δ and is excluded. Tape values count as ±5 mm.
  * `b`: day-to-day **biological variation** (posture and spinal compression for heights, about 8 mm; meals and breathing for waist, about 15 mm; and so on). These are priors, to be replaced by the user's own repeatability.
* `z = |Δ| / u_Δ`:
  * z ≥ 3 is **significant**;
  * 2 ≤ z < 3 is **possible** ("confirm with another scan"), unless a ≥ 3-snapshot weighted trend confirms the direction;
  * z < 2 is **stable** (within noise).

A single noisy reading therefore never produces a "significant" headline. Protocol differences (calibration, profile, time of day, simulated data) are listed with every comparison.

## Proportions
Shoulder ÷ waist breadth, chest ÷ waist, waist ÷ hip, arm span ÷ height, upper arm ÷ forearm, inseam ÷ height, shoulder level (left − right, from the simultaneous acromion capture), waist centre offset. These are geometric comparisons of your own body over time, **not medical or fitness diagnoses**.

## Clothing fit intelligence
* `ease = garment − body` per area (chest, waist, hip, shoulder, thigh), in the garment's own measurement direction.
* Target ease **ranges** are set per category (tee, shirt, hoodie, jacket, trousers, jeans, shorts, skirt, dress) and per fit intent (compression → oversized). Negative ease is correct for compression garments.
* Stretch fabrics extend the lower bound by ½ × stated stretch × garment dimension.
* Uncertainty-aware statuses:
  * **fits comfortably**
  * **becoming tight**: ease dropped versus the previous snapshot and now sits in the tight quarter of the range
  * **may no longer fit**
  * **currently too loose**
  * **may fit after a body change**: only when a significant measured trend points toward the range, stated as "if the trend continued, not a prediction"
  * **requires additional information**
  * **cannot be determined reliably**: the ease is within the measurement uncertainty of a limit. This is common for model-derived girths until the circumference model is calibrated.
* "Good fit" feedback teaches a personal comfortable ease per garment.
* Size recommendation ranks a product's sizes by where each sits in the target range for this body. It does not map to generic S/M/L.
* **Marvelous Designer simulation remains the detailed validation**: ease alone ignores construction, pattern, sleeve opening and drape.

The ease ranges are apparel-practice starting points, **not validated**, and are tuned through FitFeedback and MD simulations (Test 08).

## Transformation studio and video
* **Correspondence:** every snapshot's body is generated by the same parametric model (fixed rings × segments, canonical A-pose, floor origin). Vertex *i* is the same anatomical location in every snapshot, so scale and pose are standardised by construction. The topology signature is verified before interpolation, and incompatible meshes are refused.
* Modes: chronological transformation, overlay (first versus last), side by side; front, side, back, 360° or free view; Faberland gold, blue hologram, solid or skin-tone style.
* Labels are burned into every rendered frame:
  * **ACTUAL SCAN** at snapshot keyframes;
  * **INTERPOLATED VISUAL STATE** between them ("not a measurement");
  * **HYPOTHETICAL SIMULATION** for scenario bodies.
* Exports, all rendered locally with no paid service:
  * MP4 where the browser's MediaRecorder supports it, otherwise WebM;
  * a 60-frame PNG image sequence (.zip);
  * a filmstrip PNG;
  * a Markdown/JSON comparison report.

## Training programs
Programs (name, category, start and end) are compared using the nearest scans before and after. The app states that a change after a program started is an *association, not a cause*. Hypothetical scenarios show what would need to change, clearly labelled as simulations.

## Limitations
* Change thresholds use prior uncertainties until real repeatability data exists (VALIDATION.md).
* Upper arm, forearm and wrist girths are tape-only: the measured arm holds a controller.
* The body model is a measurement mannequin, not a photographic scan. Limb girths without measurements are estimated, and every mesh lists what was estimated.
* Marketplace integration (Stage G) is the host contract plus garment-specific size ranking. Checkout is out of scope for this cycle.
